  What I built: subscriptionReducer.ts (src/part-a/subscriptionReducer.ts)
  handles loading the subscription and dropping out-of-date responses. It has
  three pieces:
  - loadErrorKind: a 404 means "not found", and any other error means "failed,
    try again".
  - viewOf(server): picks the active, paused or cancelled view.
  - initialState: starts as loading, so the skeleton shows on the very first
    render.

  subscriptionReducer.test.ts (src/part-a/subscriptionReducer.test.ts) has 15
  tests for the load steps, stale responses, error mapping and viewOf.

  Two changes from the plan you approved. I updated plan.md
  (SPECS/001-a-subscription-overview/plan.md) to match and explained both in the
  changelog:
  1. The request id now sits on the whole state, not on the loading/failed
     cases. In the plan, ready had no id. The mock's delay is random, and React
     StrictMode sends two requests, so request 2 can come back before request 1.
     Request 1's late response would then overwrite fresh data, or replace it
     with an error, with nothing to tell it was stale. Now a response is ignored
     whenever its id isn't the latest, whatever state the page is in.
  2. viewOf takes the server subscription instead of the whole state. This way
     it never has to return something for a page that hasn't loaded yet. 004
     will add the local cancel as a second argument.
